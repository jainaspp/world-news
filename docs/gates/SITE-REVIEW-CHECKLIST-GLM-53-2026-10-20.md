## 1. 重大更新定義（何時觸發全站閘）

### 1.1 必須過閘（major-update triggers）

以下任一改動視為重大更新，上線前必須走全站閘（本清單 → GM 合併閘）：

| 編號 | 觸發條件 | 理由 |
|---|---|---|
| TRG-1 | 首頁布局結構改動（grid、主欄、hero 骨架） | 全站流量入口 |
| TRG-2 | 文明軸系統改動：axis-hero、deep-axis 軸、milestones 節點、axis-rails（模式／案例 pill）、今日釘、切片卡 | 即 2026-10-20 截圖出事區域 |
| TRG-3 | 全域 CSS 改動：`src/App.css`（＝`/site.css`）的 token、字級、色彩、media query 增刪 | 一改全站動 |
| TRG-4 | 導航結構改動：header、chips 列（文明／編年／開蒙／今日）、icon 鈕、語言／主題切換 | 每頁頂部都受影響 |
| TRG-5 | 動畫／視覺系統：vignette、glow、scroll-snap、starmap、過場動效 | 溢流與層互撞的高發源 |
| TRG-6 | 路由結構改動：新增或改名頁面、錨點規則（`#slice`、`#stage-N-*`） | 外鏈＋內鏈雙重風險 |
| TRG-7 | 文明／編年新厚頁上線（新的 route key＝新頁面） | 新頁必須全套覆蓋檢測 |
| TRG-8 | 固定／粘性層（CTA、banner、返回頂部）位置或行為改動 | 遮擋與互撞直接相關 |

### 1.2 免閘（快速通道，仍需單點自檢）

- typo、單篇內文修字（不動版式）。
- 單純資料針：feeds、行情、新聞列表資料更新（不動卡結構）。
- 純後端／API 邏輯（不改輸出 HTML 結構）。
- 同尺寸圖片素材替換（若改尺寸或寬度屬性 → 補跑 P1-03）。

免閘 ≠ 免檢：任何上線前至少跑一次 P0-01（橫向溢流）單點快檢，結果記在 PR 描述。

## 2. P0 必殺清單（任一 FAIL → 整次更新不得上線）

通則：P0 判定必須附 ≤640 視口實拍或模擬器截圖為證（見 §6 證據要求）。

### P0-01 橫向溢流與左右緣裁切（horizontal overflow / edge clipping）

- 覆蓋面：M、T、D × 全部頁（HP／CIV／CHR／LRN／SLC／NEWS）
- FAIL 條件（任一成立即 FAIL）：
  1. `document.documentElement.scrollWidth > window.innerWidth + 1`（任一覆蓋視口）。
  2. 肉眼可見左緣或右緣內容被裁：logo、h1、導航鈕、第一張卡、第一個編號圓、任一 pill 標籤切半。
  3. 整頁可用雙指或滑鼠水平拖動（刻意設計的單列橫滑容器本身除外）。
- 截圖對應：2026-10-20 手機圖左緣整排裁切（品牌、h1、「起源」鈕、01 號圓、多個 pill）即本項 FAIL 實例。

### P0-02 品牌字樣「文明編年史」完整呈現

- 覆蓋面：M、T、D × 全部頁
- FAIL：品牌字樣任何一字被裁、被遮、斷行斷裂，或於 M 視口不可完整讀出。
- 截圖對應：截圖只見「史」一字 → 直接 FAIL 實例。

### P0-03 固定寬度渲染陷阱（fixed-width trap）

- 覆蓋面：M × CIV、CHR、SLC 必測；T 抽查
- FAIL 條件（任一即 FAIL）：
  1. 任何內容容器的 `min-width` 超過當前視口寬（例如 560px 級圖容器在 360px 機上，必須自帶橫滑殼且不把頁面撐寬）。
  2. 負向外距（例如向兩側 −16px 的 band）在 ≤640 造成頁面級橫向滾動。
  3. 絕對定位元素把 `body` 撐寬。
- 判定方法：DevTools 逐層找 `scrollWidth > clientWidth` 的元素並記錄選擇器路徑，寫進證據。

### P0-04 觸控目標 ≥44px

- 覆蓋面：M × 全部頁（T 抽查）
- FAIL 條件（任一即 FAIL）：
  1. 任何可點元素（chips、軸節點、pill、CTA 鈕、icon 鈕、關閉鈕）可點面積 <44×44px。
  2. 相鄰可點元素中心距 <44px，造成誤觸風險。
- 已知風險點（事實記錄，本清單不改碼）：axis-hero 內按鈕 `min-height: 36px`；軸節點 12px 字＋14px 圓點 → 依本條屬 FAIL，須先修才過閘。
- 截圖對應：截圖軸 CTA（「跳到今日切片」／「起源」）與軸節點均低於 44px 門檻。

### P0-05 重疊遮擋與層互撞（overlap / z-index collision）

- 覆蓋面：M、T、D × 全部頁
- FAIL 條件（任一即 FAIL）：
  1. 任兩個可交互元素視覺重疊，或 sticky／fixed 層於任何滾動位置蓋住連結或按鈕。
  2. 固定 CTA 與粘性 CTA 同屏出現，造成雙重覆蓋。
  3. 下拉層（搜尋、主題、語言）開啟時被其他層蓋住，或無法關閉。
  4. 橫滑列滑動時把相鄰層帶走或疊上（橫滑與其它層互撞）。

### P0-06 時間軸節點可讀不重疊（deep-axis milestones）

- 覆蓋面：M × CIV、CHR 必測；T、D 抽查
- FAIL 條件（任一即 FAIL）：
  1. 任兩個軸節點標籤（例「今天切片」與「未來展望」）文字碰撞、重疊或擠壓至不可讀。
  2. 節點圓點脫離金色軌線（軌線位置固定而 flex 擠壓錯位）。
  3. 軸節點不可點或點擊目標 <44px（併 P0-04 計）。
- 截圖對應：截圖中「今天」「未來」標籤擠成一團 → FAIL 實例。

### P0-07 主導航完整可達

- 覆蓋面：M × 全部頁（HP 必測）
- FAIL 條件（任一即 FAIL）：
  1. 文明／編年／開蒙／今日 chips 任一被裁，或需 pixel-hunting 才能命中。
  2. 搜尋、主題、語言三個 icon 鈕任一不可見、被遮或 <44px（併 P0-04 計）。
- 截圖對應：截圖 header 品牌被裁，左側導航可達性存疑。

## 3. P1 應修清單（上線前應修；GM 可記錄後帶條件放行，上限見 §6）

### P1-01 暗色對比（dark contrast）

- 覆蓋面：全視口 × 全部頁
- FAIL：正文對比 <4.5:1（大字 <3:1，WCAG AA）。已知需驗組合：墨底 `#161c24` 上的 `#c5c0b6` 軸字與 `#e8e4dc` 標題；紙底 `#f7f1e6`／`#f3f5f8` 上的 `#5c6570` meta 字。

### P1-02 絕對定位堆疊可控

- 覆蓋面：M × CIV、CHR 必測
- FAIL：裝飾性絕對定位層（軌線、vignette、星點）攔截點擊（pointer-events 未隔離），或於窄視口壓到正文。

### P1-03 圖片寬度屬性收斂

- 覆蓋面：M × CIV、CHR、LRN
- FAIL：`<img>` 固有寬（如 640）超過容器且無 CSS 夾寬，撐出橫向滾動（與 P0-03 連動，單獨記錄以便追蹤修復）。

### P1-04 橫滑列 overscroll 隔離

- 覆蓋面：M × HP、CIV
- FAIL：內部橫滑列可把整頁帶成橫向平移（需 `overscroll-behavior-x: contain` 類隔離，且頁面本身零橫滾）。

### P1-05 sticky／fixed 層行為一致

- 覆蓋面：全視口 × 全部頁
- FAIL：粘性元素在滾動中覆蓋正文且無法脫離；或與返回頂部／訂閱 CTA 疊出三層以上。

### P1-06 最小字級

- 覆蓋面：M × 全部頁
- FAIL：任何非裝飾文字 <12px（軸節點 12px 為現行下限；再低即修）。

### P1-07 錨點跳轉落點

- 覆蓋面：M、D × SLC、CHR（`#slice`、`#stage-N-*`）
- FAIL：錨點跳轉後目標被 sticky header 永久遮擋。

### P1-08 編年編號卡首尾完整（01–06 號圓／卡）

- 覆蓋面：M、T × CIV
- FAIL：第一個（01）或最後一個編號卡不可見或被裁。
- 截圖對應：截圖 01 號（農業革命前一階）整個消失於左緣 → 與 P0-01 雙重 FAIL 實例。

## 4. P2 建議清單（不阻上線，滾動改善）

- P2-01：M 視口軸節點減量（例如只留「起源／今天／未來」三點）或改直式時間軸，從結構上解決標籤擠壓，而非逐條打補丁。
- P2-02：`prefers-reduced-motion` 下停用 glow、scroll-snap、starmap 動效。
- P2-03：橫向手機（M landscape，高 <420px）複查 sticky 層。
- P2-04：自動化：把 P0-01 的 `scrollWidth` 斷言寫進現有 vitest，加一張 360px 基線截圖 diff，讓閘一半交給機器。
- P2-05：品牌字樣與軸標題在閱讀器模式／列印輸出的呈現檢查（低優先）。

## 5. 截圖實證對照（本清單如何抓住 2026-10-20 手機圖的每個陷阱）

| 截圖看到的問題 | 對應檢測項 |
|---|---|
| 左緣整體裁切（logo、h1、按鈕、卡、pill 全面出血） | P0-01、P0-03、P1-08 |
| 品牌只剩「史」一字 | P0-02 |
| 內容像按固定寬度畫在窄螢上，而非自適應 | P0-03 |
| 「今天切片」「未來展望」軸標籤幾乎重疊 | P0-06 |
| 「起源」鈕被裁、無法可靠點擊 | P0-01＋P0-04 |
| 01 號編年圓整個消失於螢外 | P0-01、P1-08 |
| pill 標籤（「效率的儲存與維修」等）切半 | P0-01、P1-04 |
| 軸 CTA 高度 36px 級距、icon 鈕偏小 | P0-04、P0-07 |

結論：以本清單跑 2026-10-20 的手機版文明 hub，至少 P0-01／02／03／04／06／07 六項 FAIL → 該版本不應過閘上線。內容審（文案、資料）與視覺閘（本清單）缺一不可：本次事故正是「內容過審但無視覺閘」的直接後果。

## 6. 過關規則建議（pass rule proposal）

1. **票制**：GM 合併三份獨立清單（Kimi K3、Grok 4.7、GLM 5.3）。任一項被 ≥2 份列為 P0 → 合併閘必列 P0；只被 1 份列 P0 但附實測 FAIL 證據 → 同樣升 P0。
2. **全綠才上**：P0 全部 PASS 於「M × 全部頁」，加上 T、D 各至少一輪抽查，才可上線。任一 P0 FAIL → blocker，無條件退回，不接受「已知問題帶病上線」。
3. **P1 帳**：P1 未清項最多放行 3 條，每條須記原因、負責人與下個版本修復承諾；超過即退回。
4. **P2 不阻上線**：滾動排進後續版本。
5. **證據要求**：每項 P0 PASS 附 ≤640 視口截圖（檔名含日期與視口寬，例 `civ-360w-2026-10-21-pass.jpg`），並附 `scrollWidth` 檢查 console 輸出；截圖統一存 `docs/gates/evidence/`。無證據視為未測，未測不得宣稱 PASS。
6. **簽字**：合併閘由 GM 簽字主責；另由三大模型輪值一家覆核副署（雙簽）。部署者上線前 5 分鐘快檢 P0-01＋P0-04 兩項，結果回填 PR。
7. **免閘通道**（§1.2）只免全站閘，不免 P0-01 單點快檢；快檢結果記在 PR 描述。
