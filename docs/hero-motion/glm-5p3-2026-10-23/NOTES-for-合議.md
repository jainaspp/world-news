## 2. 本稿是什麼（一段話）

三幕全螢幕宇宙演化：第一幕古暖金（奇點→熔爐點燃波）、第二幕今冷藍（恆星灰燼→一彎佔滿下緣的行星地平線，夜面城市燈火與第一批恆星同一個金色）、第三幕未來紫黑發光（門線＋監測面板）。七拍旁白用「冷面腳註」語域（主句敘事、※ 註講笑點），settled 時 CTA 下浮現一枚**不逐秒走動**的監測讀數面板（與生產 `MONITOR_READING` 同源），底部幕標軸的行進點落在「古」——開場把棒交給三卷。

## 4. 本座的弱項（坦白）

1. **開場比較高**（789–835px vs 現行 703–805px）：監測面板佔約 60–80px。已在 360×800 首屏內容納拍 7 與面板；若合議重視更矮，可改單行緊湊面板。
2. **行星地平線比點狀地球貴**：每幀三條大弧＋百餘燈點，預算內但未在低端真機實測（接入時走 P1-PERF）。
3. **拍 7 收句較抽象**：「物質開始記錄自己」比「現在，輪到我們了」冷一點；換來的是「你讀的這一頁，已是最新一頁」把讀者直接寫進結尾。取捨，不是疏失。
4. **視覺事件多**：點燃波、超新星餘光、行星、門線、幕標軌——訊息密度高於現行版；喜歡安靜的評審可能覺得吵。凍結幀逐拍看（`?state=playing&t=…`）再下判斷比較公平。
5. **監測面板＝頁面上第二個鐘面**（見 §5）。
6. **幕標軌三刻名與三卷卡重複標記**：「古·今·未來」是預演也是重複；已 `aria-hidden`，視覺密度由合議定。

## 5. 監測鐘：本座與現行版的真正分歧點

- **現行上線版（Kimi 座）**：監測鐘完全獨立、不動；開場與鐘互不相干。
- **本座**：開場終點**落**在監測讀數上——宇宙尺度→今日儀器，再交接軸與三卷；面板與生產監測鐘同一份 `MONITOR_READING`，不逐秒走動、不重複計時。

兩案都符合「可更新的監測隱喻、非假的精確恐嚇倒數」。分歧是**敘事位置**：鐘屬站、或鐘屬開場的終點。這是合議最值得辯的一題；也可以混合（見 §6 第 3 項）。

## 6. 混合菜單（若 GM 不整稿採用）

1. GLM 天幕三層換幕（全螢幕色溫演進）＋Kimi 旁白與 canvas——最低成本的視覺升級路徑。
2. GLM 旁白（冷面腳註）＋Kimi 分鏡——零視覺風險的文案升級路徑。
3. 監測面板落點（GLM）＋鐘面獨立（Kimi）：面板只留弧形鐘面圖形、不落文字，或開場結尾只出現一行「監測讀數在下方」，完整讀數留在生產鐘。
4. 行星地平線＋城市燈火（GLM 拍 6）單獨移植到任何一稿的地球章節。
5. 幕標軌（古·今·未來＋行進點）作為任何一稿的交接 UI。
6. 點燃波（恆星隨波亮起）作為任何一稿的恆星章節事件。
