# 文明近未來加厚研究：生存危機類型學與盤點倒數（Kimi，2026-10-19）

閱讀範圍：`shared/civilization/` 的 `SCHEMA.md`、`contract.ts`、`spine.ts`、`chronicle.ts`、`chronicleMilestones.ts`、`patterns.ts`、`cases.ts`、`slices.ts`、`renderSlice.ts`、`questions.ts`、`blocks.ts`、`lineFilter.ts`、`earth.ts` 與 `content/earthStages.ts`、`functions/civilization/[[path]].ts`、`tests/civContract.test.ts`、`tests/civCases.test.ts`，以及 `docs/slice-near-bridge.md`、`docs/mainland-compliance/REPORT.md`。本頁是研究報告，不含產品代碼；所有 schema 均為提案，落地時仍走既有契約測試。

## 一、結論先行

1. **近未來不住新路由，住第十階段。** 編年 `#stage-10`「當代／近未來」是既有錨點，渲染器已自動為該階段輸出深讀塊、模式卡位與案例位。加厚未來層 = 往既有資料陣列追加物件，不新增 `PAGES` 鍵、不進網站地圖、不改 `[[path]].ts` 路由表。
2. **危機是一張「溫和解釋卡」，不是警示頁。** 建議新增 `CRISIS_CARDS` 陣列，形狀沿用 `CivCard`（問題、機制、不適用邊界、維修／傳承條件、今日可問、四條以上來源）。契約裡 `maintenance` 必填這一條，恰好是「不寫末日行銷」的結構保證：每張危機卡必須回答「什麼東西在維持它不失控」——監測網、評估程序、備援制度、師徒傳承。寫機制與維修，不寫情緒。
3. **倒數的滴答對象永遠是「下一次盤點」，不是災難。** 倒數目標只取三類已排程的公共信息事件：機構日程（年度報告、締約方大會、任務窗口）、自然週期（太陽活動週期，寫「約」窗口）、目標年（如 2030 可持續發展目標年）。倒數到「下一份評估發佈」永遠為真、永遠可更新、永不尖叫；倒數到「末日」三者皆否。這是本提案最重要的一條設計決定。
4. **更新靠機構節奏，不靠新聞情緒。** 每個倒數帶 `reviewISO` 編輯盤點日，到期自動生成刷新任務；每出一輪內容就種下下一輪任務，主線因此永不完成，也永不枯竭。一個 sprint 只能交首批，交付物的另一半是未來任務。
5. **契約需要小步修訂五處**（問題索引上限、近層 `PatternCardId` 聯合類型、`questionHrefAllowed` 白名單、案例 `related` 白名單、模式卡三卡 pin），全部是資料層改動，不動視覺。墨色 `#161c24` 與紙感 `#f7f1e6` 維持，倒數無紅色、無閃爍、無秒針。

## 二、現狀盤點：近未來薄在哪裡

`#stage-10` 目前的家當：三個里程碑（數字貨幣形態、生命科學工具、AI 通用化）、一段約百字正文、一個深讀塊（智能工具通用化）、一條來源。對比階段七（工業革命）有模式卡 `power-store`，階段四有敗篇 `gear-pause`，階段三有 `copy-check`——**第十階段沒有任何模式卡、沒有案例、沒有切片主題、問題索引十二問沒有一問指向它**。總覽的深時間板止於起源，軸上 `today` 節點直接跳去今日切片。「古」有宇宙、地球、起源三塊深時間板，「今」有切片與近層橋，中間的近未來只有一張薄卡。這正是 PP O 說的「只有古＋今」。

## 三、生存危機類型學（溫和解釋，非末日行銷）

八個類型。每一類先給一句溫和解釋，再給四線掛點、既有先例（深時間或近層）、優先來源機構。類型名本身即編輯規則：名詞指涉「系統與盤點」，不指涉「災難場景」。

| # | 類型 | 一句溫和解釋 | 四線 | 既有先例掛點 | 優先來源 |
|---|------|--------------|------|--------------|----------|
| 1 | 氣候與極端天氣 | 能量收支的長期偏移改變極端天氣的頻率分佈；全球有定期評估程序 | 能量·制度 | 遠層：地球頁「環境」欄（大氧化的深時間鏡像）；近層：國際氣象合作 | IPCC、WMO、中國氣象局氣候變化藍皮書、聯合國氣候行動頁 |
| 2 | 生物圈與類群興替 | 類群消長是深時間常態；當代問題是變化速率與監測名錄是否跟得上 | 制度·信息 | 遠層：地球頁「優勢類群」敘事；近層：紅色名錄制度 | IUCN 紅色名錄、《生物多樣性公約》、昆明—蒙特利爾框架頁、聯合國環境規劃署 |
| 3 | 淡水、土壤與關鍵資源 | 資源約束先表現為盤點與調度問題，而非突然枯竭 | 能量·制度 | 近層：現代灌溉與地下水盤點 | 聯合國糧農組織、聯合國水機制、世界銀行公共數據頁 |
| 4 | 技術系統中斷 | 電網、導航、供應鏈的風險在級聯與備件，維修制度是真正的主角 | 能量·信息 | 既有敗篇 `gear-pause`（齒輪裝置的中斷條件）是同一語法；近層：1989 年魁北克停電 | 國際能源署、北美電力可靠性公司公開報告、IEEE 公共科普 |
| 5 | 協調與標準失靈 | 多方共用一套尺需要程序維持；失靈先表現為換算成本上升 | 制度·貨幣 | 既有模式卡 `measure-promise`；近層：國際單位制沿革 | 國際計量局、國際標準化組織、聯合國區域委員會公共頁 |
| 6 | 空間天氣與近地天體 | 太陽活動與小行星是可監測的自然過程；盤點在觀測網與任務窗口 | 信息·能量 | 近層：1989 年地磁暴停電（只寫中斷條件）；正文可記 1859 年卡靈頓事件（寫「約」） | NOAA 空間天氣預報中心、ESA 空間安全計劃、中國科學院國家空間科學中心、國際小行星警報網 |
| 7 | 知識與記錄中斷 | 格式失效、語言消失、技能失傳是複製成本之外的另一條信息線 | 信息 | 既有模式卡 `copy-check`；近層：世界記憶名錄（約 1992 年起） | 聯合國教科文組織世界記憶、楔形文字數字圖書館、國家圖書館數字保存公共頁 |
| 8 | 公共衛生與監測 | 流行病的文明問題是監測網與通報程序的覆蓋與速度 | 制度·信息 | 近層：全球疫情監測網絡 | 世界衛生組織、聯合國公共健康頁 |

三條類型學紀律：

- **人只作一個物種整體出現。** 類型 2 談生物類群，沿用地球頁「優勢類群」詞彙；任何類型不按人群、地區、族群比較高下或排名。這是既有契約「不寫人群高下」的延伸，也直接回應 SPECIES 一軸的合規邊界。
- **每類必答維修條件。** 契約 `maintenance` 必填：監測網誰維護、評估程序多久一次、備件與師徒在哪裡。沒有維修答案的類型不成卡。
- **衰退歸因沿用既有語法。** 只歸因於技術、基建、環境或知識能否傳下去；標題用「中斷」「失傳」，不用刺激性詞。

## 四、倒數：一個可持續的內容物件

### 4.1 什麼在滴答

倒數物件（暫名「盤點倒數」）的目標**只能是已排程的公共信息事件**，分三類鐘：

| 鐘 | 例子 | 節奏 | 不確定性怎麼寫 |
|----|------|------|----------------|
| 機構日程 | WMO《全球氣候狀況》年度報告；《生物多樣性公約》締約方大會；IUCN 紅色名錄更新；ESA Hera 探測器抵達雙小行星系統（約 2026 年底）；國際計量大會 | 每年、約兩年、每四年 | 有確日寫日期；只有月份的寫「約 X 年 X 月」 |
| 自然週期 | 太陽活動週期（約十一年；下一極小期窗口約 2030 年前後） | 約十一年 | 永遠寫「約」與窗口，不寫確日 |
| 目標年 | 聯合國 2030 可持續發展目標年；昆明—蒙特利爾框架 2030 行動目標 | 固定年份 | 倒數到目標年，正文寫「距下一次進度盤點」而非「距最後期限」 |

**滴答的不是恐懼，是制度。** 讀者看到的句子永遠是「某機構將於何時公佈下一輪盤點」，數字是這句話的註腳。

### 4.2 來源從哪裡來

每個倒數沿用契約來源規則：至少四條 `https`，恰好一條標 `supports: 'mechanism'`，且該條必須是主辦機構的日程或程序頁（例如大會官網的會期頁、任務官網的里程碑頁）。機構改版或日程推遲時，改資料不改模板。來源偏好順序沿用合規審計：聯合國系統與條約機構、國際科學組織、博物館與公共科普頁、中國公共機構科普頁；已被封禁的外媒中文來源一律不用。

### 4.3 怎麼更新才不變成恐慌行銷

1. **靜態優先，無腳本也成立。** 無 JS 渲染：「下一次盤點：約 2027 年」。有 JS 時以 `target.iso` 計算「約 N 天」，純文字替換，無動畫；`prefers-reduced-motion` 維持原樣。秒針式倒數是恐慌的形狀，本提案明確不做。
2. **過期降級，不出現負數。** 目標日已過而機構尚未公佈下一輪時，卡片自動改為靜態句：「上一輪盤點已發佈，等待主辦機構公佈下一輪」，並把 `reviewISO` 頂到編輯眼前。頁面快取 3600 秒，天級精度天然相容，無需為倒數調快取。
3. **數字旁必有兩句溫和話。** 一句「今日可問」（≤28 字，問機制），一句「維修／傳承條件」（誰在維持這個盤點制度）。倒數永遠不單獨出現。
4. **視覺不換皮。** 沿用 `.civ-block` 紙卡；墨色 `#161c24`、紙感 `#f7f1e6`；無紅色、無警示圖標、無進度條式焦慮。缺圖時留紙印，與全站一致。

### 4.4 怎麼連回今日切片

- 新增切片主題（資料在 `slices.ts`，不新增路由）：以關鍵詞對上今日懶人包，例如 `climate-watch` 對 `氣候|升溫|極端天氣|熱浪|乾旱`。今槽寫今日問題，近槽 `precedentRef` 指向危機卡錨（`/civilization/chronicle/#crisis-{id}`）或其倒數錨，遠槽維持深時間或本地科普節點。
- 雙向規則沿用近層橋 SOP：槽與回鏈兩端一起寫，只寫一端不算完成；軸頁底部「今日可問」連回首頁 `/#near-{主題 id}`。
- 危機卡與倒數都可帶 `sliceThemeIds`（仿模式卡既有欄位），空則不渲染切片列；新聞輪換不影響近層穩定。

## 五、Schema 提案與契約接點

### 5.1 危機卡（新陣列，不動模式卡）

```ts
// shared/civilization/crises.ts（提案）
export type CrisisKind =
  | 'climate' | 'biosphere' | 'resource' | 'tech-failure'
  | 'coordination' | 'space-weather' | 'knowledge' | 'health';

export type CivLevel = '個人' | '城市' | '區域' | '全球';

export interface CrisisCard extends CivCard {
  kind: CrisisKind;
  /** 機制起作用的尺度；資料先行，LEVELS 軸的落點，UI 後做。 */
  levels: readonly CivLevel[];
}

export const CRISIS_CARDS: readonly CrisisCard[] = [/* 追加即上新 */];
```

`crisisIssues(card)` 先完整跑 `civCardIssues`，再加三條：`anchor` 首批必須是 `/civilization/chronicle/#stage-10`；`title`、`problem`、`mechanism` 不得命中禁用詞表（見第七節）；`levels` 為閉集非空子集。`lines` 不出四線閉集，危機卡因此自動進總覽四線篩選。

### 5.2 盤點倒數（獨立小陣列）

```ts
// shared/civilization/countdowns.ts（提案）
export type CountdownKind = 'assessment' | 'conference' | 'cycle' | 'mission' | 'target-year';

export interface CivCountdown {
  id: string;                     // 短橫 slug；頁內錨 #countdown-{id}
  title: string;                  // ≤16 字
  kind: CountdownKind;
  crisisId: string;               // 所屬危機卡，必須存在
  target: { iso?: string; window?: string }; // 有確日用 iso；無確日用「約 X 年」窗口，二擇一
  cadence: string;                // 機構節奏：「每年」「約兩年」「約十一年」
  mechanism: string;              // ≤120 字：這次盤點由誰、按什麼程序產生
  ask: string;                    // ≤28 字今日可問
  lines: readonly CivLine[];
  sources: readonly CivSource[];  // ≥4 條 https，恰好一條 supports mechanism
  reviewISO: string;              // 編輯盤點日：最遲何時人再看一次
  sliceThemeIds?: readonly string[];
}
```

`countdownIssues(item)`：slug、`target` 二擇一且不空、`mechanism`／`ask` 字數、來源規則（沿用 `CivSource` 檢查）、`lines` 閉集、`crisisId` 存在於 `CRISIS_CARDS`、`reviewISO` 是合法日期。倒數渲染為危機卡內的一節與總覽板上的一行紙感小字，不獨立成頁。

### 5.3 契約小步修訂清單（全部是資料層）

| # | 位置 | 修訂 | 原因 |
|---|------|------|------|
| 1 | `tests/civContract.test.ts` | 三卡 id pin 不動；另為 `CRISIS_CARDS` 加獨立 pin 與全套形狀測試 | 現 pin 鎖死模式卡為三張，危機卡必須走新陣列 |

| 4 | `cases.ts` | `CASE_RELATED` 白名單放行危機與倒數錨 | 案例的 related 至少四條且須含模式卡、階段錨、問題索引 |

## 六、掛點：總覽與軸

- **編年 `#stage-10`**：危機卡區段放在該階段深讀塊之後、來源表之前，渲染仿 `renderPatternCardsForStage`；倒數作為卡內一節。首屏收斂：單階段危機卡以四張為軟上限，其餘走問題索引與總覽板進入，`details/summary` 收合是既有行為。
- **總覽 `/civilization/`**：模式卡板之後加「危機與盤點」板（仿 `renderPatternBoard`），每卡一行紙感條目附「下一次盤點」小字；問題索引新增問句落在既有 `#question-index`。
- **軸 `spine.ts`**：**不加節點**。軸上每個節點背後都是厚頁；危機與倒數未達厚頁字數門檻前，按 SCHEMA 規矩不進網站地圖、不加 `PAGES` 鍵。近未來住在第十階段，這與「今天」節點住在切片是同一語法。未來某天真有厚頁需求，再按「一個 key 一條記錄」的路由表規矩另議，不在首批。
- **首頁近層**：新切片主題的近槽指向危機卡錨；首頁 `#near-{id}` 與總覽 `#question-index` 雙向回鏈沿用既有機制。

與 PP O 其他三軸的邊界（本報告只交付危機＋倒數軌）：**domains** 加厚屬科技、城市頁的另一軌，危機卡不開第五線；**LEVELS** 以 `levels` 欄位資料先行，UI 後做；**SPECIES** 由生物圈卡以類群詞彙覆蓋，人類作為單一物種的章節屬起源長頁延伸，不由危機卡開題。

## 七、編輯規則：讓危機永遠是教育內容

1. **三句語氣綱領**：寫機制，不寫情緒；寫盤點，不寫末日；寫維修條件，不寫束手無策。
2. **禁用詞表**（進驗證器，掃 `title`／`problem`／`mechanism`／`ask`）：末日、崩潰、恐慌、最後機會、倒數毀滅、文明終結。**允許詞表**：中斷、失傳、盤點、備援、耐受、恢復、監測、傳承。深時間的類群興替事實留在地球頁既有敘事，危機卡不搬運災難場景。
3. **數字紀律**：年代一律「約」或「主流綜述」；科學數字（濃度、溫度、速率）必附來源；不寫精確到年的預言；倒數只對已排程事件，目標推遲時寫「主辦機構調整會期」，不寫「倒數重置」以外的猜測。
4. **合規紅線**：沿用測試中的 REDLINE 正則全量掃描新陣列與渲染結果；不觸及測試紅線所列的敏感政治詞表；不寫國別排名、地緣對抗與軍備敘事；國際治理只寫聯合國框架與多邊程序；來源避開合規審計已移除的外媒中文與被封鎖機構；不作投資建議、不作生存主義指南（沿用第十階段「只寫工具與形態」的現句）。
5. **人群紀律**：不寫族群優劣，不做人群、地區、文明排名；敗篇只寫中斷條件；類群詞彙只用於生物。
6. **圖像紀律**：墨色紙感不變；倒數無紅色、無閃爍、無動畫；缺圖留紙印；`civ-reveal` 與 `prefers-reduced-motion` 原樣。

## 八、主線運營環：claim → draft → gate → ship → refresh

這是一條 MAINLINE 長期管線。每一格都有明確產物與閘門，任何一筆內容（一張危機卡、一個倒數、一篇案例、一次刷新）走同一條環。

| 格 | 動作 | 產物 | 閘門 |
|----|------|------|------|
| claim 認領 | 從 backlog 表取一筆，開資料分支；backlog 永存於 docs，每筆帶 id、掛點、來源清單、reviewISO | 分支與認領註記 | 一筆只一個物件；不跨軌 |
| draft 起草 | 只改資料檔；先列來源再寫句；寫滿契約欄位；切片主題與回鏈兩端一起寫 | 資料物件與來源清單 | 無模板分支、無新路由、無新 `PAGES` 鍵 |
| gate 閘門 | 契約測試全綠；紅線掃描通過；字數與來源規則通過；人工審讀對照禁用詞表與三句綱領 | 綠 CI 與審讀記錄 | 任一不過即退回 draft |
| ship 上線 | 合併；核對三處掛點（編年錨、總覽板、首頁近層）雙向鏈；無 JS 靜態文案成立 | 上線錨點 | 來源表去重正確；網站地圖無新增文明路徑 |
| refresh 盤點 | `reviewISO` 到期開新任務；機構出新一輪報告時更新機制句、數字與來源；每季全量 URL 體檢與禁用詞表複查 | 更新提交與下一個 `reviewISO` | 過期倒數必須已降級為靜態句 |

**內容日曆（永不完成）**：日曆由機構出版節奏驅動，不由新聞情緒驅動；每 ship 一筆就種下它的 refresh 任務，故任何單一 sprint 都只能完成「首批」。

| 節奏 | 驅動事件 | 產生的任務 |
|------|----------|------------|
| 每年 3–4 月 | WMO《全球氣候狀況》上年度報告 | 氣候卡機制句與數字盤點；`wmo-annual` 倒數重設 |
| 每年數次 | IUCN 紅色名錄更新 | 生物圈卡數字與來源刷新 |
| 約兩年 | 《生物多樣性公約》締約方大會 | 生物圈卡＋`cbd-cop` 倒數重設 |
| 評估週期內多次 | IPCC 全會與報告發佈窗口 | 氣候卡機制來源盤點；`ipcc-ar7` 倒數重設 |
| 每四年 | 國際計量大會；聯合國可持續發展高峰會 | 協調卡與 `measure-promise` 對照刷新；`sdg-2030` 進度句 |
| 約十一年 | 太陽週期預測更新 | 空間天氣卡窗口句（寫「約」） |
| 任務窗口 | Hera 抵達（約 2026 年底）及其後任務盤點發佈 | 近地天體倒數由「抵達」改掛「盤點發佈」 |

| 每季 | 固定體檢 | 全量 URL、紅線詞表、到期 `reviewISO` 清掃 |

## 十、風險與緩解

| # | 風險 | 等級 | 緩解 |
|---|------|------|------|
| R1 | 危機詞彙誤觸紅線掃描 | 中 | 新陣列併入既有 REDLINE 測試；起草期本地先跑；詞表由測試單一真源維護 |

## 十一、不做清單

不新增 `/civilization/` 路由與 `PAGES` 鍵；不進網站地圖；不換皮（墨色 `#161c24`、紙感 `#f7f1e6` 不變）；不做秒針式或紅色倒數；不寫精確到年的預言；不寫人群、地區、國別排名；不觸及測試紅線所列的敏感政治詞表；不使用合規審計已移除的來源；不作投資或生存主義建議；不為危機與倒數另起一套產物／推動力欄位（沿用 `CivReadingShape`）。
