# K07 · 雙層模式（敘事層＋索引層）

> **結論先行：** 首頁一個開關兩層——「敘事層」是新客路徑：Hero→三卷故事卡→`#slice`→鐘→開蒙；「索引層」是回客工具：主題×十階交叉矩陣、熱門厚頁、最新切片列表。十案之中唯一正面回答「首訪講故事、回訪查資料」這對矛盾；代價是兩層內容必須同源生成，否則一年後必然漂移，且索引層需要一份階×主題映射表的新資料結構。

- **id:** K07
- **title:** 雙層模式·敘事索引
- **one_liner:** 講故事模式與查資料模式，一個開關兩個首頁。

## sitemap

```
/                          首頁雙層（?mode=story|index，預設 story，index 層 canonical 指 /）
/civilization/             三卷總覽
/civilization/chronicle/   編年正文（#248 行為不變）
/civilization/cosmos|earth|origins|tech|city/   五厚頁保留
/topic/                    既有主題頁，升級為索引層支柱
/learn/                    開蒙（獨立產品線，兩層都有入口）
新聞舊路由                  保留為切片後台
```

未來不開新路由：敘事層的卷三卡與索引層的未來階列都指向 `#future` 章門與編年未來段。

## home_wire

1. **首屏：** BBT 式幽默開場＋全螢幕宇宙演化動畫＋模式開關（敘事｜索引，segmented ≥44px×2）。
2. **第 2 屏（敘事層）：** 三卷故事卡（古→今→未來，卷色）→ `#slice` 今日切片 → 監測鐘（隱喻式）→ 開蒙入口。
3. **第 2 屏（索引層）：** 主題×十階交叉矩陣（列＝主題，行＝階，格內是內容計數與入口）→ 熱門厚頁五連 → 最新切片列表（十則，比敘事層的三則更深）。
4. 兩層共用 Hero 與頂底欄；開關狀態寫入 `?mode=` 與 localStorage，回客記住偏好。

## nav

- **頂欄：** wordmark｜編年｜主題｜開蒙｜切片——「主題」是索引層的常駐入口，不依賴開關被發現。
- **底欄：** 全站文字索引＋CC BY 4.0＋方法學與關於。

## mobile（390）

- 開關 sticky 於 Hero 下緣，兩格各 ≥44px 高。
- 索引矩陣不用橫滑（防橫溢陷阱），改為手風琴：主題為節、階為節內項目，每行 ≥44px。
- 敘事層與 K01 同構，直向滾動；切片列表直排大觸控行。

## visual

- **色區：** 敘事層卷色飽和（金／藍／紫黑發光）；索引層中性灰底，卷色縮小為標籤與階點——用色彩飽和度區分「看故事」與「查資料」兩種腦態。
- **字階：** 敘事層三級（28／20–24／16–17px）；索引層壓平（18／15–16px）以密度換掃讀。
- **動效層級：** 重＝Hero 動畫（兩層共用）；輕＝模式 fade ≤200ms、手風琴展合。

## migration（相對現況）

1. **保留：** 五厚頁、chronicle 及 #248 行為、`/topic/` 既有路由與資料。
2. **改：** 首頁殼雙模式化；新聞模組降為敘事層三則＋索引層十則。
3. **新增：** 階×主題映射表（content manifest 一份，索引層據此生成，禁止手寫第二份）。
4. **砍：** 首頁新聞皮。
5. **成本：** 中高——映射表資料結構是真正新增；分「敘事層殼→索引層＋映射表」兩個 PR 上閘。

## risk（Top 3）

1. **內容漂移：** 兩層若各寫一份，一年後必然矛盾——對策：索引層只讀 content manifest，映射表是唯一事實來源，CI 檢查孤兒節點。
2. **SEO：** `?mode=index` 若被收錄會稀釋首頁權重——對策：index 層 canonical 指 `/`，索引層所有連結在 `/civilization/` 與 `/topic/` 有穩定落地頁。
3. **開關認知成本：** 訪客可能永遠不知道有第二層——對策：頂欄「主題」直達索引層落地頁，開關只是捷徑，不是唯一入口。
