## 結論

未來要變成主線，就得變成**可每週追加的資料**，掛在已經上線的錨上。編年固定十個階段，`chronicleIndexable` 要求 `CHRONICLE_STAGES.length === 10`。宇宙、技術、城市同樣鎖在十段，地球鎖在八段。第十一階段、軸上的「未來」節點、`/civilization/future/` 這一類新路由，都會把主線做成一次性專頁。

厚度放在編年 **`#stage-10`（當代／近未來）** 之內，分四份可增長的陣列：

1. **未來域**：開放目錄。一筆是一個題材，聲明自己碰到四線裡的哪一至兩條。
2. **讀數帶**：能量通量、信息校驗、維修能動三軸上的條件帶。帶是基礎設施的狀態，可以退回。不設總分，不採用任何一家的等級制。
3. **類群框**：溫和的科學與條件句。沿用地球頁的「類群」和起源頁「不討論族群優劣」。不設種族欄，不寫優生，不寫人群高下。
4. **維修窗口**：生存壓力寫成「維修一旦停止，先失效的是哪一項功能」，並標時距。不設倒計時鐘，不寫日期預言。

四線閉集維持 **能量、信息、制度、貨幣**。生命、度量、類群、能動、棲居都是題材或別的命名空間，不升為第五條線。軸的順序維持宇宙 → 地球 → 起源 → 技術 → 城市 → 今天（`#slice`）。編年是軸旁的十階段帶，不是 `spine.ts` 裡的一個節點。

近未來今天很薄：第十階段只有一段散文、一枚深讀塊 `#stage-10-product`，四線只標貨幣與信息，沒有模式卡、案例，問題索引也不指向它。管道的第一程是把域目錄和一張模式卡掛進這個錨，讓軸上的紙感入口自己長出來。

## 現況

### 軸與頁

`SPINE` 的順序是資料本身：

| 節點 | 年份標 | 網址 |
|---|---|---|
| 宇宙 | ~138億 | `/civilization/cosmos/` |
| 地球 | ~40億 | `/civilization/earth/` |
| 起源 | ~300ka | `/civilization/origins/` |
| 技術 | 發現 | `/civilization/tech/` |
| 城市 | 基建 | `/civilization/city/` |
| 今天 | 切片 | `#slice`（`now: true`） |

`functions/civilization/[[path]].ts` 的 `PAGES` 只有空路徑、`cosmos`、`earth`、`origins`、`tech`、`city`、`chronicle`。其餘路徑 404 且 `noindex`。`SCHEMA.md` 寫明：加內容只改資料，不新增 `/civilization/` 路由，也不按卡片編號在渲染器裡寫分支。

編年十階段由 `renderChronicleStrip` 放在軸下，由 `renderStageGrid` 放在總覽。深時間三張卡來自軸上帶 `board` 的節點。讀法是宇宙接到地球，地球在約七百萬年前交起源，編年再用四線重讀同一條河。技術頁與城市頁各有自己的線名，末端都交回今日切片，不另寫一套未來。

### 四線與另外三套線

`CivLine` 只有四項，順序固定。契約寫明：宇宙頁的物質、時間，地球頁的環境、類群，技術頁的工具、能源、媒介、知識，都是別的命名空間。城市頁是聚落、工程、交通、民生。度量是模式卡的題目。

因此未來域可以**碰到**四線，並在相關處回指宇宙的能量、地球的類群、技術的工具、城市的民生，但不把那些線名寫進 `CivLine`。

### 第十階段實際寫了什麼

`chronicle.ts` 第 10 段：

| 欄位 | 現文 |
|---|---|
| 名稱 | 當代／近未來（短標：近未來） |
| 年代 | 約公元 2000 年代至今 |
| 里程碑 | 數字貨幣形態、生命科學工具、AI 通用化 |
| 意義 | 貨幣、生命與智能的技術形態同時改寫（溫和科技敘事） |
| 四線 | 貨幣、信息 |
| 主來源 | 中國錢幣博物館官網，`http://www.cnm.com.cn/` |

深讀塊「智能工具通用化」（`#stage-10-product`）的產物是電子錢包與數字貨幣實驗、測序與編輯工具、大模型與智能代理。推動力是信息、貨幣、知識成本。散文要求只記工具與形態，不作預測，不作投資建議，並把今日新聞切片掛回軸的末端。

三張模式卡分別掛在 `#stage-7`、`#stage-3`、`#stage-6`。兩篇案例掛在科技 `#tech-7` 與編年 `#stage-4`。問題索引十二條，沒有一條的 `href` 落在第十階段。

切片 `slices.ts` 的「今｜近｜遠」是**今日標題、較近先例、較遠先例**。能源的「近」回到功率儲存，度量的「遠」回到起源。這裡的「遠」是深時，不是遠未來。若把「遠」改成未來，近層橋會倒過來。

### 契約裡會卡住未來的幾處

這些是主線必須順著走的鎖，不是建議。

| 鎖 | 位置 | 對未來的含義 |
|---|---|---|

| 模式卡 id 被測試寫死為三張 | `tests/civContract.test.ts` | 第四張卡要同時改這條斷言，並改掉總覽裡「三張模式卡」的寫死句子 |
| 切片的 `PatternCardId` 是三張的聯合型別 | `slices.ts` | 近層要引用新卡時才放寬型別；前幾步不必動切片 |
| 問題索引 8–12 條，現為 12 條 | `questionIndexIssues` | 總覽不能再加一問，除非改上限，或在第十階段另開一份不計入總覽的問句 |

| 案例相關連結的正則 | `CASE_RELATED` | 可連模式卡、`#stage-N`、技術、地球、起源、問題索引、近層。不認識里程碑子錨 |
| 深讀塊第二塊的錨 | `milestoneBlockAnchor` | 同階段 `index > 0` 時，錨是 `#stage-N-{slug}-{序號}`。第二塊即使 slug 為 `repair`，也會得到 `#stage-10-repair-2` |

## 未來域

域是開放清單。新域是陣列裡的新物件。域不是頁，也不是第五條線。

每一域必須同時寫清四件事：碰到哪一至兩條 `CivLine`、時距、主張的把握（已發生、進行中、可能），以及一個已經上線的錨。把握寫成「可能」的域，正文用條件句，並標「未發生」。

首批目錄八筆。前四筆進入第一個增量；後四筆等前四筆的錨穩定後再追加。這樣目錄從一開始就預留生長位，又不會一次寫滿。

| id | 域 | 線 | 時距 | 把握 | 主錨 | 回指 |
|---|---|---|---|---|---|---|
| `energy-budget` | 行星能量收支 | 能量 | 數十年 | 進行中 | `#stage-10` | 模式卡 `power-store`，宇宙能量線 |
| `verify-flood` | 複製氾濫之後的校驗 | 信息 | 進行中 | 進行中 | `#stage-10` | 模式卡 `copy-check`，`#stage-9` |
| `life-tools` | 生命科學工具 | 信息 | 數十年 | 進行中 | `#stage-10` | `#stage-10-product` 已有的測序與編輯句 |
| `clearing` | 清算與信用形態 | 貨幣、制度 | 進行中 | 已發生且仍在改寫 | `#stage-10` | `#stage-8` |
| `spare-grid` | 儲存、輸配與備件 | 能量 | 數十年 | 進行中 | `#stage-10` | `#stage-7` |
| `pipe-care` | 城市維生管網 | 制度 | 進行中 | 進行中 | `#stage-10` | 城市頁末端、城市線「民生」 |
| `long-office` | 跨世代機構連續 | 制度 | 世紀 | 進行中 | `#stage-10` | 模式卡 `measure-promise` |
| `closed-habitat` | 封閉棲居的後勤 | 能量、制度 | 未發生 | 可能 | `#stage-10` | 地球「環境」，城市「工程」 |

`life-tools` 的題材是生命，線仍是信息：工具改變的是可核對的記錄與實驗步驟。生命不進 `CivLine`。`closed-habitat` 預設不進前八個增量的上頁範圍，先留在目錄說明裡，等 GM 點頭再寫成資料。

域的邊界句沿用模式卡的寫法，每句都是一個「不等於」：

- 能量收支被記下來，不等於分配跟著改善（`power-store` 已有這句）。
- 複製近乎免費，不等於記錄為真（`copy-check` 已有這句）。
- 清算變快，不等於信用自動在場。
- 測序變便宜，不等於出現一種新的人，也不等於實驗可以離開實驗室規範。
- 封閉棲居在工程上可被討論，不等於定居已經發生。

## 讀數帶

等級若做成一條梯子，未來就會變成排名。本站要的是三軸上的**條件帶**：某一帶成立，是因為能量、校驗或維修還在場。維修中斷，帶就退回。帶不對應人群，不加總，不印成「文明第幾級」。

### 六套既有框架，各取一句

下列對照用於選軸，不用於選一個學派當站內制度。

**卡爾達舍夫，1964。** 論文題為 *Transmission of Information by Extraterrestrial Civilizations*（*Soviet Astronomy* 8:217，ADS `1964SvA.....8..217K`）。原文按可調用功率分三型：I 型接近當時地球的能量消耗，約 `4×10^12` 瓦；II 型為恆星輸出量級，約 `4×10^26` 瓦，並以戴森球為例；III 型為星系量級，約 `4×10^37` 瓦。論文同時假設消耗每年增約百分之一，則約三千二百年達到太陽輸出、約五千八百年達到約 `10^11` 顆太陽的輸出。後來的複述常常把 I 型改成「用盡到達行星的全部能量」，並用小數給地球一個分數。兩套分型本站都不用。可取的只有一句：行星尺度的功率與恆星尺度的功率不是同一件事。原文那條增長外推是倒計時，維修窗口不採用它。

**巴羅，1998，《Impossibility》。** 討論科學在更小尺度上碰到的操控限度。後人把它整理成相對卡爾達舍夫的「向內尺度」。可取的是「操控半徑」這個問法：生命科學與材料是向分子與細胞尺度延伸的工具。不取一套向內的文明等級，以免「更能操控」被讀成「更高級的人」。

**柴森的能量流率密度。** Eric J. Chaisson 以單位時間、單位質量通過系統的能量（常記為 Φm）串起星系、恆星、行星、生命與社會，作為複雜度的一個代理量。公開綜述見其 *The Natural Science Underlying Big History*（PMC4086236）與 2011 年文稿。可取的是：宇宙頁的能量與編年頁的能量可以共用「能流」這個詞，而且絕對能量大不等於結構更複雜。不取他的數值表。*Journal of Big History* 對該指標的再檢視指出：它常量的是總能流而不是自由能，效率更高的系統可能顯得「更不複雜」，也不能單獨充當複雜度的金標準。站內正文只保留問句，不印數量級排行。

**斯米爾的能量轉型。** Vaclav Smil，*Energy and Civilization: A History*（2017）。一次能源的更替是長期重疊，不是舊燃料在新機器到場那天退出。轉換有損失，人均一次能源也不是分配的結果。這與 `power-store` 的邊界同向：可用功率提高，不等於分配跟著改善。

**莫里斯的社會發展指數。** Ian Morris，*The Measure of Civilization*（2013），四項是能量獲取、組織、戰爭能力、信息技術，並給出東西分數。可取的是多軸、可按歷史時段書寫。戰爭能力不進本站的軸。東西分數、指數表與「誰領先」的敘事不進資料。制度線已經負責「陌生人能否核對與接手」，不必再引入一套國家評分。

**泰恩特，1988，《The Collapse of Complex Societies》。** 複雜度是解決問題的策略，有維修成本；邊際報酬下降時，複雜度可以很快失去。可取的是「退回」與案例契約裡的敗篇：敗只寫中斷條件。不把中斷寫成道德教訓，也不把失去複雜度寫成某一群人的失敗。

能動性另有阿馬蒂亞·森《以自由看待發展》（1999）的「可行能力」：一個人實際能夠做什麼、成為什麼。可取的是把能動從產值裡分開。不在站內做地區發展指數。

### 本站三軸

三軸的操作定義如下。

| 軸 | id 前綴 | 問的是 | 不問的是 |
|---|---|---|---|
| 能量通量 | `e` | 可調度的功從哪裡來，能否儲存、送出、在斷供後修回 | 誰的文明更高、距離 I 型還有多遠 |
| 信息校驗 | `i` | 記錄離開現場之後，誰對底本 | 每日產生多少比特、模型是否更真 |
| 維修能動 | `a` | 原班人離開之後，同一項功能能否被陌生人做回去 | 意志、智商、種族資質、模型是否成為主體 |

帶的 id 穩定，標籤可以改字，不改 id。

| id | 條件 | 退回時發生的事 | 已可標上的既有階段 |
|---|---|---|---|
| `e0` | 可用的功主要來自身體代謝 | 食物中斷則活動半徑收縮 | 地球早期代謝，只作自然史對照，不進四線 |
| `e1` | 身體以外的火與生物質 | 火塘與燃料知識中斷，夜與食的範圍退回 | 編年 1，技術頁用火 |
| `e2` | 農牧剩餘與畜力 | 倉儲或牲口中斷，不耕作的分工退回 | 編年 2 |
| `e3` | 熱機或電力可儲存、可輸配，且備件在場 | 備件或師徒中斷，功率退回機房之內 | 編年 7，`power-store` |
| `e4` | 行星尺度的收支與存量被記錄，功率仍受備件與轉換損失約束 | 存量或輸配中斷，高通量退回 `e3` 或更低 | 尚無。留給 `energy-budget` |
| `i0` | 學習靠當面示範 | 人不在，步驟就停 | 技術頁石器以前的交接 |
| `i1` | 口傳可離開當下，仍無底本 | 傳承鏈斷則內容不可覆核 | 編年 1，技術頁口傳 |
| `i2` | 書面可被複製 | 無校驗則錯誤隨複本走遠 | 編年 3，`copy-check` |
| `i3` | 複製已經便宜，且尺、底本或編校在場 | 校驗機構中斷則退回 `i2` | 編年 5–6，`measure-promise`，印刷案例 |
| `i4` | 複製的邊際成本近乎消失，瓶頸轉到出處與核實 | 核實中斷則協作半徑把錯誤放大 | 編年 9–10 的工具形態；帶本身仍待 `verify-flood` 寫明 |
| `a0` | 中斷即失傳 | 無文本、無備件 | 作為退回的底，不單獨表彰某一階段 |
| `a1` | 親緣或師徒能把手順傳下去 | 師徒鏈斷則退回 `a0` | `power-store` 的維修句 |
| `a2` | 文本讓陌生人接手 | 檔案或程序中斷則退回師徒 | 編年 3–4 |
| `a3` | 度量、備件與信用能跨區維持 | 換算或清算中斷則跨區功能停 | 編年 6 與 8 |
| `a4` | 工具可以起草，責任與接手仍在人與制度 | 出處或責任中斷，起草仍在，功能不可覆核 | 編年 10 的目標帶，現文尚未寫成條件 |

編年每一階段將來在側表裡得到一個三元組，例如工業階段是 `e3 · i3 · a1`。三元組是標籤，不是分數。第十階段今天只能誠實標成「貨幣與信息的工具形態已寫，`e4` 與 `a4` 尚未寫成條件」。不把「近未來」直接印成 `e4·i4·a4`。

圖例放在 `#stage-10` 的紙卡裡。階段卡首批不加讀數帶，避免十張卡同時改臉。

## 類群框

地球頁的線名裡已有「類群」。各階段的「優勢類群」指該時段在生態上顯著、化石上可對照的類群。第一階段寫微生物的氧化還原生態位，第八階段寫明：人族出現不表示其他類群退場，只表示此後的敘事可以改從人族化石寫起。分類位置隨新標本修訂。

起源頁開篇已寫：不討論族群優劣、政治地理分界或領土歸屬；基因交流只作生物學事實的溫和說明。聯合國教科文組織 1978 年《種族與種族偏見宣言》第一條寫明，全人類屬於同一物種，出自共同祖先，尊嚴與權利平等；生活方式的差異不得用作偏見的藉口（UNESCO 法律文本：<https://www.unesco.org/en/legal-affairs/declaration-race-and-racial-prejudice>）。

未來的物種可能，沿這兩句往下寫。資料欄名用 `cladeFrame`（類群框）。不設「種族」欄，不設優生欄，不設資質分數，不設「改良人」等級。

| id | 框 | 把握 | 主張 | 邊界 | 錨 |
|---|---|---|---|---|---|
| `tool-extension` | 同一物種的工具延伸 | 綜述 | 智人是一個物種。文字、電網、測序與模型延長的是可交出去的功能，不是亞種名單 | 文化與醫療差異不構成物種分裂，也不構成人群高下 | 起源頁，並由 `#stage-10` 回指 |
| `niche-continue` | 生態位延續 | 綜述 | 未來生物圈的變化仍用地球頁的文法：環境、類群、產物、推動力。作物、牲畜、微生物是生態位上的類群 | 「優勢」只指該時段的生態顯著，不指價值高低 | `#earth-1`、`#earth-8` |
| `isolation-condition` | 隔離分化的條件 | 條件句 | 只有在長期地理隔離、基因流極低、並跨過許多世代時，分類才可能改寫。這是地球史已經用過的問法 | 現生人類沒有這樣一組條件。本框不描述、不設計任何分離 | 預設不上頁。若 GM 開，只回指地球頁「分類隨標本修訂」 |
| `habitat-agent` | 棲居條件與工具代理 | 未發生／工具 | 封閉棲居問的是能量閉環、信息延遲與備件。模型與機器是產物（技術或制度），不是類群 | 工具可以起草，不因此成為一種人，也不進入類群頁 | 預設不上頁。與 `closed-habitat` 同一道門 |

`isolation-condition` 是這四框裡最容易滑出科學說明的一框。前八個增量不把它寫上頁面。研究結論是：條件句可以存在於目錄說明，正文先只上 `tool-extension` 與 `niche-continue`。

生命科學工具停留在第十階段已有的句子：測序成本下降，編輯工具進入實驗室與臨床研究，公共場館以溫和方式講解原理。未來增量可以補「責任在制度、底本在記錄」，不補操作步驟，不寫增強等級，不寫病原體。

## 維修窗口

生存壓力不做成午夜鐘，也不做成「還有多少年」。原子科學家公報的午夜隱喻、以及卡爾達舍夫原文的增長外推，都是公眾熟悉的倒計時。本站的「今日可問」不是動員句。窗口用時距枚舉：

`進行中` · `數年` · `數十年` · `世紀` · `深時` · `未發生`

每扇窗口四句話：若維修停止，先失效的功能是什麼；要維持，什麼必須在場；把握與不確定寫到哪裡；錨在哪。

| id | 窗口 | 域 | 時距 | 先失效的功能 | 必須在場 |
|---|---|---|---|---|---|
| `carbon-stock` | 能量存量與收支 | `energy-budget` | 數十年 | 可調度的功率不再按舊的燃料與輸配表交付 | 收支記錄、儲存、備件、可核對的單位 |
| `source-debt` | 出處債務 | `verify-flood` | 進行中 | 複本仍在流動，底本不可對 | 出處、編校、可退回的原文 |
| `clearing-stop` | 清算中斷 | `clearing` | 進行中 | 遠距交換停在「錢已付出、貨與賬對不上」 | 清算規則、可核對的單位、爭議程序 |
| `city-pipes` | 城市管網 | `pipe-care` | 進行中 | 水、能源或通行在街段上中斷 | 圖紙、備件、輪替的人手 |
| `clade-redundancy` | 類群冗餘減少 | `niche-continue` | 數十年至世紀 | 生態位上的替代者變少，食物網更依賴少數路徑 | 地球頁已有的類群文法，以及棲地本身 |
| `outbreak-check` | 疫情訊息的校驗 | `verify-flood` | 進行中 | 消息先於核對到達 | 公共衛生機構的公開說明與可對照的記錄 |
| `waste-steward` | 長壽期裝置的看守 | `long-office` | 世紀 | 看守機構換屆之後，義務沒有文本可交接 | 跨世代的程序與公開清單 |
| `closure-spare` | 封閉系統的備件 | `closed-habitat` | 未發生 | 後勤一旦不能從外部補充，閉環先斷在備件 | 能量賬、備件與信息延遲的說明 |

`outbreak-check` 只寫校驗與公開說明，不寫病原、不寫任何製作或繞過篩查的方法。`waste-steward` 若 GM 不開，就不上頁；能量危機只保留收支、電網備件與城市管網。`closure-spare` 與封閉棲居同一道門。

時距在頁上用既有的 `.line-chip`，墨色 `#161c24`、紙感 `#f7f1e6`。不新增時鐘、進度條或警報色。

窗口的公開入口，首批用機構首頁級的綜述，不摘數值當預言：

- 能量收支：IPCC 綜合報告入口 <https://www.ipcc.ch/report/ar6/syr/>，以及站內已用的美國能源信息署能量解說。
- 類群冗餘：IPBES 全球評估入口 <https://www.ipbes.net/global-assessment>，回指地球頁來源，不另造物種價值表。
- 疫情訊息：WHO 突發衛生事件入口 <https://www.who.int/emergencies>，只作「有公開機制」的先例。
- 清算：站內已用的國際貨幣基金組織年表。
- 城市管網：城市頁已用的聯合國教科文組織遺產入口，只說明工程可被核對。

## 如何掛上四線與軸

```
軸（spine.ts，不增節點）
  宇宙 → 地球 → 起源 → 技術 → 城市 → 今天 #slice

編年帶（仍是十段）
  … → 09 信息革命 → 10 當代／近未來
                         │
                         ├─ 未來域        錨 #stage-10，各自帶四線 chips
                         ├─ 讀數帶圖例    三軸條件，不計分
                         ├─ 維修窗口      時距章，用既有 line-chip
                         ├─ 模式卡        anchor 已允許 #stage-10
                         └─ 案例          beside: stage-10

回指，不把未來寫進深時頁
  宇宙能量  ←—— 能流這個詞，不印 Φm 表
  地球類群  ←—— niche-continue
  起源      ←—— tool-extension，以及已有的「不討論族群優劣」
  技術末端  ←—— 工具新聞仍回今日切片
  城市末端  ←—— pipe-care 的民生
```

掛載規則：

1. 一條未來資料只選一個主錨。相關階段放在 `related`，不複製正文。
2. 第十階段的階段卡維持「一至兩條線」的版式，現有貨幣、信息兩枚芯片不動。域自己的芯片寫在域塊上，因此能量與制度可以出現在第十階段內部，而不把階段卡改成四線全亮。
3. 總覽四線篩選只認 `CivLine`。域若要參加篩選，必須整組 `lines` 都在四線裡，並出現在總覽實際會收合的區塊上。前幾個增量只渲染在編年第十階段內部，不進總覽篩選，避免篩選腳本與域目錄互相綁死。
4. 模式卡一旦 `anchor` 為 `#stage-10`，現有渲染會把它放進該階段、總覽模式卡全文，以及軸下的紙感入口。這是主線「自己長出來」的接口。
5. 切片的「遠」維持深時先例。未來域不佔「遠」槽。近層以後若要指向第十階段，只改「近」或「今」的先例連結，並放在問題索引契約改完之後。
6. 宇宙頁、地球頁不增收未來段落。地球第八階段最多在日後加一句回指，指向第十階段的類群框，且仍在約七百萬年交接。那一句不在前兩個增量裡。

建議的資料門是一個模組，而不是四套新頁：`shared/civilization/future.ts` 匯出四個唯讀陣列，編年第十階段呼叫一次渲染。渲染復用 `renderReadingBlock` 與 `.civ-block`，模式卡繼續走 `patterns.ts`。視覺只增加必要的錨，不增加皮。

## 資料形狀

下列形狀對齊 `CivReadingShape`、`CivCard` 與 `CivSource`。本檔只提案，不落程式。

```ts
type FutureHorizon = '進行中' | '數年' | '數十年' | '世紀' | '深時' | '未發生';
type FutureStatus = '已發生' | '進行中' | '可能';
type LevelAxis = '能量通量' | '信息校驗' | '維修能動';
type CladeKind = '同一物種的工具延伸' | '生態位' | '隔離分化的條件' | '棲居與工具代理';

interface FutureDomain extends CivReadingShape {
  id: string;                 // 英文短橫 slug
  title: string;
  lines: readonly CivLine[];  // 一至兩項，閉集
  horizon: FutureHorizon;
  status: FutureStatus;
  /** 已上線的錨。首批一律 /civilization/chronicle/#stage-10 */
  anchor: string;
  problem: string;            // ≤ 40
  mechanism: string;          // ≤ 120
  boundary: string;           // ≤ 80
  maintenance: string;
  ask: string;                // ≤ 28，含「如何｜能否｜靠什麼」
  sources: readonly CivSource[];
  bandIds: readonly string[]; // 指向 LevelBand.id，可空
  frameIds: readonly string[];
  windowIds: readonly string[];
}

interface LevelBand {
  id: string;                 // e0–e4、i0–i4、a0–a4
  axis: LevelAxis;
  label: string;              // 條件，不是人群
  holds: string;
  reverses: string;
  /** 已經能指認的階段。空陣列表示帶尚未被正文寫實 */
  mounts: readonly { page: 'chronicle' | 'earth' | 'tech' | 'city' | 'cosmos'; n?: number }[];
}

interface StageBandMark {
  /** 編年階段號 1–10。側表，不改 ChronicleStage 的必填欄 */
  stage: number;
  bands: readonly [string, string, string]; // 能量、信息、能動各一
}

interface CladeFrame {
  id: string;
  title: string;
  kind: CladeKind;
  status: '綜述' | '條件句' | '未發生';
  claim: string;
  boundary: string;
  /** 起源頁、地球階段，或編年第十階段 */
  anchor: string;
  publish: boolean;           // 前八個增量裡，條件句與未發生為 false
}

interface MaintenanceWindow {
  id: string;
  domainId: string;
  horizon: FutureHorizon;
  breaks: string;
  holds: string;
  uncertainty: string;
  anchor: string;
  sources: readonly CivSource[];
  publish: boolean;
}
```

字數、來源與「恰好一條機制來源」與模式卡相同，以便日後把成熟的域提升為 `CivCard` 時不必改句子。域目錄本身可以比模式卡寬：允許先有四筆域、一張卡。卡是可調用的機制，域是可生長的目錄，兩者不要合成一個陣列。

第十階段子錨的穩定做法：域的頁內錨用 `#future-{id}`，窗口用 `#window-{id}`，讀數帶圖例用 `#level-bands`，類群框用 `#frame-{id}`。這些錨都在 `/civilization/chronicle/` 上，不新開路徑。問題索引在契約修訂前不指向它們；修訂時只把通過 `publish === true` 的錨加入允許清單。

深讀塊的第二錨不要假設為 `#stage-10-repair`。在 `milestoneBlockAnchor` 改為「顯式且唯一的 slug 不加序號」之前，第二塊的真實錨是 `#stage-10-{slug}-2`。增量六要么接受這個錨，要么連同測試改錨點函數。兩者不要混用。

## 非目標

本主線不做下列事項。

- 不新增 `/civilization/` 路由，不加 `PAGES` 鍵，不為未達厚頁門檻的卡片進網站地圖。
- 不加編年、宇宙、技術、城市的第十一階段，不加軸節點「未來」。
- 不把 `CivLine` 擴成生命、度量、能動、類群或棲居。
- 不採用卡爾達舍夫 I／II／III 型、其小數分數，或其增長外推。
- 不印柴森的能量流率密度數值表。
- 不引入莫里斯的戰爭軸、東西分數與指數表。
